# Mona Art — Implementation Status

Mona Art is a native Android painting studio: its own brush engine, own
compositor, own document format and exporters, no third-party paint engine and
no network access. This document states exactly what works, what is partial and
what is still missing. Every claim below is backed by a test, a self-check, or a
code path that ships in the debug APK.

- Version: 1.0.0 (versionCode 1), document format v3
- Module layout: `:engine` (pure-JVM painting core) + `:app` (Compose UI, Android)
- minSdk 26, target/compileSdk 37, Kotlin 2.4.21, AGP 9.4.1
- Build status: see `BUILD_REPORT.md`, regenerated by CI on every push and citing the commit it actually built

## Partially done — be honest about these

| Item | What exists | What is missing |
|---|---|---|
| **Canvas rendering path** (L1) | Engine composites only the visible rect (max 2560 px) into a bitmap, blitted once per dirty region | The bitmap upload still happens on the UI thread; a GPU path (or `ImageBitmap` double-buffer + `RenderNode`) is planned for 4K canvases |
| **Transform tool** (L2) | Drag moves the layer; scale and rotation are live sliders with Apply/Reset, each gesture one undo step | On-canvas transform handles (grab-and-drag corners) are not implemented; the tool options panel drives scale/rotation instead |
| **Liquify** (L3) | Working push tool with radius/strength options, per-gesture undo | No separate "twirl / pinch / bloat" liquify modes |
| **PSD import** (L4) | PSD **writing** with layers works | Importing PSDs is not implemented |
| **Brush stamp images** (L5) | `BrushKind.STAMP` + `stampImage` field + Asset Library | No custom stamp import UI; procedural brushes only |
| **Brush preset sharing** (L13) | Export a preset as JSON through the Android share sheet; import by pasting JSON | No file-picker based import |
| **SVG export** (L6) | Not implemented | — (was listed as "later" in the brief) |
| **WebP export** (L7) | Not implemented | Removed intentionally rather than faking an encoder |
| **Onboarding** (L8) | Tip cards wired to `showOnboardingTips` | No multi-step first-run tour |

## Known limitations

- **L1 — Physical stylus verification.** No stylus hardware, emulator or adb
  access exists in the build environment. Input is verified by synthetic
  `MotionEvent` streams (pressure, tool type, tilt-axis presence, palm window,
  gesture routing) and by code review against the Android input documentation.
  Tilt behaviour on a real EMR/AES digitizer has **not** been physically tested.
- **L9 — Performance numbers.** Reported numbers come from the CI runner's JVM
  (and from a local JVM for stroke micro-benchmarks),
  not from a phone GPU. They guard against regressions; they are not device FPS
  claims. 60/90/120 Hz device profiling remains to be done on hardware.
- **L14 — Where the debug APK lives.** Every green `android` run uploads the build
  as the `mona-art-build` artifact and publishes `BUILD_REPORT.md` as a job
  summary. The workflow no longer creates a rolling release or commits the
  report. Use the manual `publish-apk` workflow for a downloadable release.
- **L10 — Instrumentation tests.** Phase 0 added `EditorSmokeTest` and CI now
  compiles `:app:assembleDebugAndroidTest`. No emulator runs it yet, so no
  on-device result is claimed.
- **L11 — Release signing.** The release AAB is built, minified and *debug-signed*
  unless `MONA_KEYSTORE_PATH`/`MONA_KEYSTORE_PASSWORD`/`MONA_KEY_ALIAS`/
  `MONA_KEY_PASSWORD` are provided. It is not publishable as-is.
- **L12 — Localisation.** English only; strings are centralised but not
  translated.
